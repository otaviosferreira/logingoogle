05 / TOKENS E PROTEÇÃO

Conheça as peças do OAuth 2.0

Cada parâmetro tem uma função específica no processo de autenticação e autorização.

04
ID TOKEN

Identidade

JWT que representa a autenticação do usuário. Deve ter assinatura, emissor, expiração e audiência validados.

ACCESS TOKEN

Acesso à API

Credencial que permite chamar APIs Google dentro dos scopes concedidos. Não serve como prova direta de identidade.

REFRESH TOKEN

Renovação

Permite obter novos access tokens sem pedir autorização novamente, conforme política do provedor. Deve ficar protegido no servidor.

AUTHORIZATION CODE

Código temporário

É recebido no callback e trocado por tokens no backend. Não deve ser tratado como access token.

CLIENT ID / SECRET

Identificação do cliente

O Client ID identifica a aplicação. O Client Secret autentica o cliente confidencial no backend.

SCOPES

Permissões

Definem quais recursos a aplicação solicita, como openid, email e profile.

STATE

Proteção CSRF

Valor aleatório associado à sessão e comparado no callback para impedir respostas OAuth forjadas.

PKCE

Proteção do código

Vincula o código de autorização a um verificador secreto, usando desafio S256, reduzindo risco de interceptação.

REDIRECT URI

Destino autorizado

URL cadastrada no Google para receber a resposta do fluxo. Deve corresponder exatamente à configuração.

✓
O navegador não é a autoridade.

O backend valida o ID token com a biblioteca oficial, cria uma sessão no servidor e envia apenas um cookie HttpOnly ao navegador.
